    Hone Tutorials¶

    Welcome to the Hone tutorial documentation. These guides will help you get started, configure providers, integrate tools, and deploy Hone securely.

    Quick Start¶

    Start here if you're new to Hone:

    1. Getting Started — Install, build, and run your first session (20 min)
    2. Providers — Configure model providers and switch between them (15 min)

    Complete Guides¶

    For Users¶

    • Getting Started — Prerequisites, building from source, first interactive session, one-shot mode, understanding output (token streaming, tool calls, cost tracking)

    • Providers — Configuring Anthropic API, OpenAI (and custom endpoints like DeepSeek, OpenRouter, Qwen), Ollama (local), CLI pass-through tools, ACP, hot-swapping providers, fallback chains, model routing rules, pricing tables, cost tracking, health checks, custom timeouts

    • Tools and MCP — Layer architecture (L0–L3), native tools (file, shell, git, LSP, semantic index), MCP integration (JSON-RPC, external tools), Code Mode (agent-generated orchestration), skills (HONE.md conventions), tool registry and dispatch, writing custom tools

    • Recipes — YAML recipe system, recipe format with annotations, conditional steps, TDD hook (test_cmd), running recipes interactively or in batch mode, recipe output and export, writing and sharing recipes

    For Operators¶

    • Server and Remote — Starting the daemon (honed), REST API overview (sessions, turns, SSE events), real-time streaming with Server-Sent Events, tunnel support (Cloudflare, Ngrok), authentication (bearer tokens), collaborative sessions, health checks, running multiple daemons, systemd integration

    • Security — Hardened sandbox architecture (Seatbelt on macOS, Landlock on Linux, seccomp on containers), path traversal prevention, shell command classification, SandboxPolicy (file/network restrictions), network deny-by-default, RBAC roles and policies, audit logging, memory encryption (AES-256-GCM with Argon2id), ephemeral mode, threat model, best practices, troubleshooting

    Learning Paths¶

    Path 1: Interactive Agent (30 min)¶

    1. Getting Started — Set up and run first session
    2. Providers — Switch between models

    You can now use Hone interactively to ask questions, analyze code, and run shell commands.

    Path 2: Automated Workflows (45 min)¶

    1. Getting Started — Set up
    2. Recipes — Define multi-step workflows
    3. Tools and MCP — Extend with custom tools

    You can now automate complex tasks via YAML recipes.

    Path 3: Team Deployment (60 min)¶

    1. Getting Started — Set up
    2. Server and Remote — Run the daemon
    3. Security — Configure sandboxes, RBAC, memory encryption, and audit logging
    4. Providers — Set up cost tracking, fallback chains, and custom endpoints
    5. Configuration — Fine-tune context optimization and budgets

    You can now deploy Hone as a multi-user HTTP service with audit logging, access control, and encrypted memory.

    Path 4: Custom Integration (90 min)¶

    1. Getting Started — Set up
    2. Tools and MCP — Integrate external tools
    3. Providers — Hot-swap providers based on task type
    4. Server and Remote — Expose via HTTP API

    You can now build custom applications on top of Hone.

    Typical Use Cases¶

    Use Case: Code Review¶

    Start with Getting Started, then use Recipes to automate the review process:

    name: "Code Review"
steps:
  - name: "Analyze Changes"
    prompt: "Review the diff and identify issues"
  - name: "Suggest Improvements"
    prompt: "What are the top 3 improvements?"
  - name: "Generate Summary"
    prompt: "Write a review summary"
test_cmd: "cargo test"

    Run it:

    hone --recipe code-review.yaml

    Use Case: Semantic Code Search¶

    Start with Getting Started, then use Tools and MCP to access the semantic index:

    hone -i "Find functions that handle authentication"

    The agent calls the semantic_search tool (Layer 2 native) to search by meaning.

    Use Case: Multi-User Team Workspace¶

    Start with Server and Remote, then configure Security for RBAC:

    honed --port 7777 --config /etc/hone/config.toml

    Multiple users can now create sessions and collaborate via the REST API.

    Use Case: Custom Tool Integration¶

    Start with Tools and MCP to write an MCP server:

    # Your custom MCP server
python3 my-mcp-server.py

    Then configure it in config.toml:

    [[mcp_servers]]
name = "custom"
command = "python3"
args = ["my-mcp-server.py"]

    The agent can now call your custom tools.

    Quick Reference¶

    Commands¶

    # Interactive session
hone

# One-shot command
hone -i "List files in src/"

# Run a recipe
hone --recipe my-recipe.yaml

# Switch model
hone --model ollama:llama2

# Set budget limit
hone --budget 10.00

# Run daemon
honed --port 7777

# Connect to remote daemon
hone --server-url https://hone.example.com --auth-token "token"

    Configuration¶

    # Config location
~/.config/hone/config.toml

# Edit
$EDITOR ~/.config/hone/config.toml

    Session Management¶

    # List sessions (daemon only)
curl http://localhost:7777/sessions

# Get session info
curl http://localhost:7777/sessions/sess_abc123

# Delete session
curl -X DELETE http://localhost:7777/sessions/sess_abc123

# Stream events (SSE)
curl http://localhost:7777/sessions/sess_abc123/events

    Troubleshooting¶

    Can't find Hone after building¶

    # Make sure you added to PATH
export PATH="$PWD/target/release:$PATH"
hone --version

    API key not found¶

    export ANTHROPIC_API_KEY="sk-ant-..."
hone

    Or create ~/.config/hone/config.toml:

    [providers.anthropic]
api_key = "sk-ant-..."

    Sandbox error on macOS¶

    This is rare. See Security Guide troubleshooting section.

    Out of memory¶

    The conversation history is too long. Clear the session:

    /clear
