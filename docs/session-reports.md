# Session Reports

At the end of each interactive session, Hone generates a detailed **session report** documenting cost, tokens, files touched, tools used, memory activity, and phase transitions. Reports are written to `.hone/reports/` and can be listed, viewed, and compared via the `hone reports` CLI.

## When Reports Are Generated

**Interactive TUI sessions only** (currently):
- Reports are written automatically when you type `/quit` or press `Ctrl+C`.
- Filename: `.hone/reports/<timestamp>-<session-id>.md` (plus `.md.json` sidecar).
- Includes full TurnLedger data from all completed turns.

**Currently not supported** — reports are **not yet** generated for:
- Recipe mode (`--recipe`)
- Orchestration mode (`--orchestrate`)
- Ensemble mode (`--ensemble`)
- One-shot mode (piped prompt, no interactive turns)

These modes are planned for a follow-up. For now, reports are only available in interactive TUI mode.

## Report Location

Reports are stored in `.hone/reports/` relative to your working directory (project root):

```
your-project/
├── .hone/
│   ├── reports/
│   │   ├── 1744531200-auth-session.md
│   │   ├── 1744531200-auth-session.md.json
│   │   ├── 1744617600-refactor-loop.md
│   │   └── 1744617600-refactor-loop.md.json
│   └── audit.jsonl
└── src/
```

**Recommendation**: Add `.hone/reports/` to your `.gitignore`. Reports may contain file paths, command outputs, and tool arguments that are best kept local:

```
# .gitignore
.hone/reports/
```

(Note: `.hone/plan.md` and `.hone/plan/` are already in the default `.gitignore`.)

### JSON Sidecar Format

Each `.md` report has a corresponding `.md.json` sidecar with machine-readable data:

```json
{
  "session_id": "auth-session",
  "mode": "interactive",
  "total_cost_usd": 0.0847,
  "tokens_in": 18530,
  "tokens_out": 4221,
  "cache_read_tokens": 2350,
  "turn_count": 8,
  "elapsed_secs": 343,
  "files": [
    {
      "path": "src/auth.rs",
      "reads": 4,
      "writes": 2,
      "execs": 0
    },
    {
      "path": "src/session.rs",
      "reads": 3,
      "writes": 0,
      "execs": 0
    }
  ],
  "tools": [
    {
      "name": "read_file",
      "count": 12,
      "total_duration_ms": 540,
      "cache_hits": 8,
      "failures": 0
    }
  ],
  "retries": 0,
  "errors": 1,
  "memory_writes": 2,
  "memory_reads": 5,
  "skeleton_strategy": "CallGraph",
  "skeleton_tokens": 2450,
  "skeleton_files": 3,
  "phase_transitions": [
    ["Exploration", 1000],
    ["Editing", 3200],
    ["Verification", 1500]
  ],
  "trace_id": "abc123def456",
  "model": "claude-sonnet-4-5",
  "timestamp": "2026-04-13 12:45:30",
  "partial": false
}
```

**JSON Schema:**

| Field | Type | Description |
|-------|------|-------------|
| `session_id` | string | Session or task name |
| `mode` | string | `interactive`, `recipe`, `orchestrate`, `ensemble`, `one-shot` |
| `total_cost_usd` | number | Total API cost (USD) |
| `tokens_in` | integer | Prompt tokens consumed |
| `tokens_out` | integer | Completion tokens produced |
| `cache_read_tokens` | integer | Tokens from prompt cache hits |
| `turn_count` | integer | Number of completed agent turns |
| `elapsed_secs` | integer | Wall-clock duration in seconds |
| `files` | array | File operation summaries (path, reads, writes, execs) |
| `tools` | array | Tool invocation statistics (name, count, duration, cache_hits, failures) |
| `retries` | integer | Number of tool call retries (not yet tracked) |
| `errors` | integer | Number of tool call failures |
| `memory_writes` | integer | Memory entries written (not yet tracked at ledger level) |
| `memory_reads` | integer | Memory entries recalled |
| `skeleton_strategy` | string &#124; null | Context injection strategy (Flat, CallGraph, Adaptive, etc.) |
| `skeleton_tokens` | integer &#124; null | Total tokens in skeleton injection |
| `skeleton_files` | integer | Count of files in skeleton |
| `phase_transitions` | array | Phases and elapsed time: `[["name", ms], …]` |
| `trace_id` | string &#124; null | Distributed trace ID (if `--audit` enabled) |
| `model` | string | Model name (e.g., `claude-sonnet-4-5`) |
| `timestamp` | string | ISO 8601 timestamp of report generation |
| `partial` | boolean | `true` if audit data is incomplete (no `--audit` flag) |

## Using the `hone reports` CLI

### List Recent Reports

```bash
$ hone reports list
```

Shows the 20 most recent reports (sorted newest-first):

```
REPORT ID                           SIZE
─────────────────────────────────────────────
1744531200-auth-session            3.2k
1744617600-refactor-loop           5.1k
1744704000-perf-tune               2.8k
… 47 more (use --limit 0 to see all)
```

**Options:**
- `--limit N` — Show only the first N reports (default: 20). Use `--limit 0` to see all.

### Show a Single Report

```bash
$ hone reports show 1744531200-auth
```

Prints the full markdown report to stdout (no pager). ID prefix matching is supported: provide enough characters to disambiguate.

Examples:
```bash
hone reports show auth          # matches "1744531200-auth-session"
hone reports show 2026-04       # matches all reports from April 2026
hone reports show 174           # ambiguous — provide more characters
```

### Diff Two Reports

```bash
$ hone reports diff 1744531200-auth 1744617600-refactor
```

Shows a line-level unified-diff-style comparison of two reports. Useful for understanding what changed between sessions.

```diff
--- 1744531200-auth-session
+++ 1744617600-refactor-loop
 
 | Session / task ID | `auth-session` |
-| Duration | 5m 43s |
-| Turns | 8 |
+| Duration | 12m 18s |
+| Turns | 15 |
-| Total cost | $0.0847 |
+| Total cost | $0.1920 |
```

## Retention

By default, Hone keeps the **100 most recent reports** in `.hone/reports/`. When a new report is written and the count exceeds 100, the oldest reports are deleted automatically.

**Retention is enforced every time a report is written** — there is no configuration option to disable it. If you want to preserve an older report, consider moving it outside the `.hone/reports/` directory:

```bash
mkdir -p ~/hone-archive
mv .hone/reports/1744531200-auth-session.md* ~/hone-archive/
```

The `--keep-all` flag on `hone reports list` shows all reports without filtering by the limit, but does not disable retention during writing.

## Privacy

Reports are written **locally only** to `.hone/reports/` — they do not phone home or upload anywhere. However, they may contain:
- **File paths** in your project
- **Tool arguments** (e.g., shell commands, grep patterns)
- **Timestamps and cost data**
- **Model name and provider information**

**Recommendation**: Add `.hone/reports/` to `.gitignore` and do not share reports in public forums without review.

## Known Limitations & Future Work

- **Reports only in TUI mode** — Currently reports are only written when exiting an interactive TUI session (`/quit`). Recipe, orchestration, ensemble, and one-shot modes do not yet generate reports. This is planned for a follow-up pass.
- **Sharing & export** — A future `/share-report` command is planned for collaborative report sharing (encrypted upload + link). For now, reports are local-only.
- **Retention configuration** — The retention limit is currently hardcoded to 100 reports. An environment variable to customize this is planned.

## Frequently Asked Questions

**Q: Can I disable auto-report generation?**  
A: Not yet. Reports are always written on session end. There is no `--no-reports` flag currently.

**Q: Can I change the retention limit from 100?**  
A: Not yet. The limit is hardcoded to 100. Environment variable configuration is planned.

**Q: How do I share a report with a colleague?**  
A: For now, manually copy the `.md` and `.md.json` files. A `/share-report` command with encrypted upload is planned.

**Q: What if I run `hone` with `--recipe`? Will it generate a report?**  
A: Not yet. Only interactive TUI mode generates reports in this release. Recipe/orchestration/ensemble modes are on the roadmap.

**Q: Are reports encrypted?**  
A: No, they are plain-text markdown + JSON. If you have enabled memory encryption (`--features encrypted-memory`), the memory *data* is encrypted, but the report *metadata* (read counts, duration, cost) is still plain-text.
